Séjours guestFlow dans Sowel

Plugin guestFlow · spec 001 · v0.4.0 · à valider avant de coder

En bref

  • Même lecture horaire, même signature : le plugin lit en plus le bloc stay de chaque clé.
  • Il publie un équipement « Séjours <logement> » : occupied, arrival, departure.
  • guestFlow éteint : il continue sur la dernière liste lue, gardée sur disque.

Vue générale — un séjour, du logiciel au radiateur

Identique dans les 3 dépôts. Modifie le séjour ou l'heure : les 4 blocs suivent.

1 · guestFlow répond à GET /gate/keys

    
2 · Clé du portail (inchangé)

    
3 · Équipement Sowel « Séjours  » nouveau

    
4 · Recette « Chauffage intelligent », Chambre Nord

  

  







  
Ce qui change dans ce dépôt

  

    
LectureInchangée (GET /gate/keys, 1 h, bouton « Relever maintenant »). Le bloc stay est facultatif : une clé sans lui reste valide.

    
Clés portailInchangées (accès partagés, fenêtre −3 h / +2 h, retour des résultats).

    
ÉquipementsUn device par logement (property-<id>), nommé d'après guestFlow. occupied bascule à l'heure exacte d'arrivée et de départ, par minuterie, sans attendre la lecture suivante.

    
MémoireLa dernière liste est écrite dans le dossier de données du plugin : un redémarrage de Sowel pendant que guestFlow est éteint ne perd pas les séjours.

    
Accès partagés coupésAujourd'hui le plugin passe en erreur. Demain : les séjours sont publiés quand même, les clés sont signalées « accès partagés désactivés ».

    
RefusSéjour de plus de 31 jours, ou départ avant l'arrivée : ignoré pour le chauffage comme pour le portail, et signalé à guestFlow.

  





  
Hors périmètre · risque

  
    
    
  • Pas d'autre endpoint, pas de nouveau secret, pas de nom de client dans l'équipement.
    • 
    
  • Risque : une annulation faite pendant que guestFlow est injoignable n'est vue qu'à la lecture suivante (au pire, on chauffe un logement vide).
